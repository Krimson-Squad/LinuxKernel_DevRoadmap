# Lesson 10.6: Writing Kernel Modules in Rust (extended)

## Overview

This is the hands-on companion to 10.2: a minimal module, the `no_std` constraints you will hit, and the build+test loop, with enough detail to write one from memory.

## Minimal module, trait-based

```rust
use kernel::prelude::*;

module! {
    type: Greet,
    name: "greet",
    author: "You",
    description: "print a greeting on load",
    license: "GPL",
}

struct Greet;

impl kernel::Module for Greet {
    fn init(_name: &'static CStr, _module: &'static ThisModule) -> Result<Self> {
        pr_info!("greeting the kernel from Rust\\n");
        Ok(Self)
    }
}

impl Drop for Greet {
    fn drop(&mut self) {
        pr_info!("dropping Greet at unload\\n");
    }
}
```

Unload runs `Drop`, so you get the exit path for free.

## `no_std` — what actually changes

- No `std::String`/`std::Vec` — use `kernel::alloc::{KString as String, vec::Vec}`.
- No `std::thread`, `std::sync` — kernel threads via `kernel::thread`, locking via `kernel::sync::{Mutex, SpinLock}`.
- No `println!` — `pr_info!`/`pr_debug!` map to `printk`.
- Panics convert to kernel aborts — handle errors with `?` and `Result` instead.

## Common pitfalls checklist

- Borrowing kernel-owned data past a callback? Store it in the crate's module struct, not a global.
- `unsafe` needed? Only at the C boundary — and justify it in a comment.
- Big stack locals? Kernel stacks are small (8-16 KiB); box the big buffers.
- Sleeping in atomic context? The type system marks them (`SpinLockIRQSafe` etc.), but respect them.

## Build + load loop

```bash
make LLVM=1 -j$(nproc)                             # after enabling CONFIG_RUST
sudo insmod greet.ko && dmesg | tail -1           # "greeting the kernel..."
sudo rmmod greet && dmesg | tail -1               # "dropping Greet at unload"
```

## Exporting a callable function

```rust
#[no_mangle]
pub extern "C" fn rust_exposed_value() -> i32 {
    42
}
```

This symbol is callable from C modules after declaring it in the header (advanced; normally abstractions handle this).
