# Lesson 10.1: Rust in the Linux Project Overview

## Overview

Since 6.1 the Linux kernel can be built from Rust: modules written in Rust compile into the same vmlinux/modules as C code. Rust is not replacing C overnight — it is being added where its guarantees pay off most.

## Why Rust for the kernel

- **Memory safety** — the #1 class of kernel bugs (buffer overflows, use-after-free, double-free) is rejected by the compiler at build time.
- **Fearless concurrency** — data races checked statically; the borrow checker stops shared-memory races.
- **Modern tooling** — `cargo`, `rust-analyzer`, built-in tests, and linting support a safer development loop.
- **A/B with C**: C stays for the majority of the codebase; Rust integrates through safe wrappers.

## Linux's goals for Rust

From the kernel's `Documentation/rust/`:

- Keep C and Rust **interoperable** — C can consume Rust modules and vice versa.
- Provide **safe abstractions** around the raw kernel API before exposing it to Rust code.
- Preserve performance — "no overhead" is the bar.

## Where it stands

- Kernel 6.1: initial infrastructure merged (`rust/` for tooling, `samples/rust/`, `drivers/rust/` for module support).
- In-tree modules so far: the `rnull` (null block driver) sample and a growing set of abstractions (`rust/kernel/`).
- Everything else — bindings, drivers, Rust-based subsystems — is being built up slowly, rate-limited by maintainer review.

## Key directories

```text
rust/            kernel Rust infrastructure and build tooling (make LLVM=1)
rust/kernel/     the safe abstraction layer (core::kernel)
samples/rust/    runnable examples including modules
Documentation/rust/
```

## Suggested exercise

Read `Documentation/rust/quick-start.rst`. Then grep `Compile-time` for `rust` in `.config` (`CONFIG_RUST=y`) and check that your toolchain (`clang`, `bindgen`, a nightly rustc) satisfies the version requirements.
