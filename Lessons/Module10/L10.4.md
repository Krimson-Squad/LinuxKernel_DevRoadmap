# Lesson 10.4: Submitting Rust-Based Patches

## Overview

Rust patches travel the same healthy path as C ones — `git format-patch`, `get_maintainer.pl`, mailing list review — with extra scrutiny on `unsafe`, toolchain versions, and rules confirmed with `CONFIG_RUST`.

## Patch requirements, Rust-specific

- **Toolchain pin**: state the exact pinned rustc/clang in the cover letter; the tree builds against a specific nightly.
- **`unsafe` discipline**: every `unsafe` block gets a comment justifying why *this* use is safe; reviewers will ask.
- **No `std`**: keep `no_std`; import from `kernel::` alloc/sync.
- **Abstractions first**: prefer extending `rust/kernel/` wrappers over leaking raw bindings.

## Preparing the patch

```bash
git format-patch -1 --stdout > /tmp/0001-rust-foo.patch
./scripts/checkpatch.pl /tmp/0001-rust-foo.patch     # style gate
./scripts/get_maintainer.pl /tmp/0001-rust-foo.patch
```

Message style matches C patches (`rust: <area>: ...` in the subject), plus `Link:` entries referencing `Documentation/rust/` or upstream discussion.

## The &quot;reproducible tests&quot; ask

Maintainers want a command you ran, not claims:

```text
Tested-by: You <you@example.com>
Test: make LLVM=1 defconfig; scripts/config -e RUST; make LLVM=1 -j8
      insmod rust_minimal.ko && rmmod rust_minimal.ko    (dmesg checked)
```

## Community involvement

- Join the **rust-for-linux** mailing list and review C-to-Rust ports.
- Declare interest on `Documentation/rust/` review threads; the Rust side is small enough that visible reviewers get fast responses.

## Exercise

Prepare a `[PATCH v1]` for a one-line documentation fix inside `Documentation/rust/` (a typo or a missing toolchain note). Run `checkpatch` and `get_maintainer.pl`, and write the exact `To:`/`Cc:` line and `Tested-by:` remark.
