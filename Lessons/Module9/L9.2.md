# Lesson 9.2: Developing Kernel Modules

## Overview

A kernel module is code that plugs into a running kernel — no rebuild or reboot required. Modules let you experiment with kernel APIs while keeping the core kernel untouched.

## Module anatomy

```c
#include <linux/init.h>
#include <linux/module.h>

static int __init hello_init(void)
{
	pr_info("hello, module\n");
	return 0;
}

static void __exit hello_exit(void)
{
	pr_info("goodbye, module\n");
}

module_init(hello_init);
module_exit(hello_exit);
MODULE_LICENSE("GPL");
```

- `module_init(...)` runs on load; `module_exit(...)` runs on unload.
- `__init`/`__exit` mark functions that are freed after use.
- `MODULE_LICENSE("GPL")` is mandatory for kernel API access.

## Build skeleton (`kbuild`)

A `Makefile` for an out-of-tree module:

```makefile
obj-m += hello.o
KDIR := /lib/modules/$(shell uname -r)/build

all:
	$(MAKE) -C $(KDIR) M=$(PWD) modules
clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean
```

Build with `make` — requires kernel headers installed (`sudo apt install linux-headers-$(uname -r)`).

## Load, test, unload

```bash
sudo insmod hello.ko          # load: runs module_init
dmesg | tail                  # -> "hello, module"
lsmod | grep hello            # registered module
sudo rmmod hello              # unload: runs module_exit
dmesg | tail                  # -> "goodbye, module"
```

`modprobe` handles dependencies and `modules.dep`; `insmod` is the minimal loader.

## Debugging a module

- Add `pr_debug` and use `dyndbg` to toggle at runtime.
- Check `rmmod` frees everything — leaks only show as machine-wide memory growth.
- Test with an unloaded/reloaded cycle to catch `__init` ordering bugs.
