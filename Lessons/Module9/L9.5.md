# Lesson 9.5: Networking in the Kernel

## Overview

User-space sockets are the tip of a stack that runs deep in the kernel: sockets → protocol layer (TCP/UDP/IP) → neighbor/ARP → netdev driver → NIC. This lesson maps that stack and the code that implements it.

## The stack, from user space down

```text
socket()/send()         user space API
  socketcalls -> sys_...   net/socket.c
  sk_buff, struct sock     core networking (net/core/, include/linux/skbuff.h)
  TCP: tcp_v4_sendmsg       net/ipv4/tcp.c
  IP routing: ip_queue_xmit  net/ipv4/route.c
  neighbor: ARP/ND           net/core/neighbour.c
  net_device_ops -> driver   drivers/net/ethernet/...
  ->
```

## Key objects

- `struct socket` / `struct sock` — one per open socket / connection.
- `struct sk_buff (skb)` — the network buffer everyone passes around; owns the packet while headers are added/removed at each layer.
- `struct net_device` — one per interface (`eth0`, `lo`, ...), with `net_device_ops` for the driver.
- `struct net_ops`/`packet_type` — protocol registration (`ipproto` handlers).

## Socket programming (user side)

```c
int fd = socket(AF_INET, SOCK_STREAM, 0);
struct sockaddr_in a = { .sin_family = AF_INET, .sin_port = htons(80) };

connect(fd, (void *)&a, sizeof a);
send(fd, "GET / HTTP/1.0\r\n\r\n", 18, 0);
close(fd);
```

Every one of these lines is a system call into `net/socket.c` before protocol code takes over.

## Interface management

```bash
ip link show        # net_device view
ip addr             # addresses
ip route            # kernel routing table
ss -tnp             # sockets and their processes
```

## Suggested exercise

Use `ss -tnp` to list a live TCP connection, then run `tcpdump`/`tracefs` while downloading a file. Follow the packet path: open `net/ipv4/tcp.c`, find `tcp_v4_sendmsg` comment flow, and identify where the `skb` is handed to the netdev `ndo_start_xmit`.
