# Lesson 6.2: Process Management in Linux

## Overview

Processes are the kernel's unit of execution isolation. The scheduler decides which task runs next, and the whole lifecycle — fork, exec, sleep, exit — is driven by the scheduler and process table.

## Core structures and files

- `task_struct` — one per task, defined in `include/linux/sched.h`.
- The scheduler code lives in `kernel/sched/`: `core.c`, `fair.c` (the CFS default class), `rt.c`.
- Process accounting and signals live under `kernel/`.

## The process lifecycle

- **Creation**: `fork()`/`clone()` build a child `task_struct` that shares or copies the parent's resources. The underlying syscalls are `sys_clone` (used by threads) and `sys_fork`.
- **Execution**: the child calls `execve()` to replace its image with a program.
- **Scheduling**: the run queue manages `RUNNING` state; `sleep()`/`wait` put tasks in `TASK_INTERRUPTIBLE`; a wakeup brings them back.
- **Exit**: `exit()` sets `TASK_ZOMBIE`; the parent's `wait()` reaps it.

`ps` shows the view from user space:

```text
PID  : unique id assigned by the kernel
PPID : parent's pid
STAT : state (R running, S sleeping, Z zombie, ...)
```

## Watching it in action

```bash
ps aux | head           # all tasks, user view
cat /proc/1/status      # kernel view of one task (init)
ls /proc/sys/kernel/sched*   # scheduler knobs
```

## The scheduler in brief

Since Linux 2.6 the default class is CFS (Completely Fair Scheduler, `kernel/sched/fair.c`). It keeps tasks in a red-black tree ordered by virtual runtime (`vruntime`) and picks the task that has run the least, providing fairness without a fixed time-slice arithmetic.

## Suggested exercise

Trace process creation: `strace -f bash -c 'exit 0' 2>&1 | grep -E 'clone|execve'` to see the clone+execve pair, then open `kernel/fork.c` and find `copy_process()` where the new `task_struct` is assembled.
