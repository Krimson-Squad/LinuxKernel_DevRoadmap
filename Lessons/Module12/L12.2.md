# Lesson 12.2: Implementing Kernel Security Features

## Overview

Beyond fixing bugs, the kernel ships whole security frameworks that constrain what even privileged code can do. This lesson covers mandatory access control, loadable security modules, and hardening config.

## Access control: SELinux and AppArmor

- **SELinux** (Security-Enhanced Linux) — mandatory access control (MAC) with a strict policy engine; labels subjects (`processes`) and objects (`files, sockets`) in a policy database.
- **AppArmor** — path-based confinement: per-application profiles (`/etc/apparmor.d/`) describe the file/network capabilities a program may use.

```bash
getenforce                # SELinux state (enforcing / permissive / disabled)
aa-status                 # AppArmor profiles and mode
```

## LSM — the Linux Security Module framework

`LSM` is a hook system (`security/`) that lets security modules intercept operations: `security_file_open`, `security_socket_create`, etc. Both SELinux and AppArmor are LSMs, and custom modules can be written to add policy:

```c
// security/example/
static int my_file_open(struct file *file)
{
	pr_info("policy: open %s\n", file->f_path.dentry->d_name.name);
	return 0;
}
static struct security_hook_list my_hooks[] __lsm_ro_after_init = {
	LSM_HOOK_INIT(file_open, my_file_open),
};
```

Register via `security_add_hooks()` in `init_my_lsm()`.

## Hardening the kernel (config side)

- `CONFIG_STRICT_KERNEL_RWX` / `STRICT_MODULE_RWX` — mark kernel text read-only + data non-executable.
- `CONFIG_RANDOMIZE_BASE` — KASLR.
- `CONFIG_STACKPROTECTOR` — stack canaries.
- `CONFIG_MODULE_SIG_FORCE` — require signed modules.
- `CONFIG_SECURITY_LOCKDOWN_LSM` — lockdown mode restricting privileged operations.

```bash
# view what's enabled in your running kernel
zcat /proc/config.gz | grep -E 'SECURITY|LOCKDOWN|SELINUX|APPARMOR|RANDOMIZE'
```

## Suggested exercise

Check your running kernel's security posture: `getenforce`, `aa-status`, and grep `/proc/config.gz` (or `/boot/config-$(uname -r)`) for `SECURITY`, `LOCKDOWN`, `RANDOMIZE_BASE`. Then write a one-paragraph AppArmor-compatible policy idea for a daemon you run (its reads, writes, and network access).
