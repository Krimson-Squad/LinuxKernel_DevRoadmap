# Lesson 4.3: **Linux File System Hierarchy**
[![Linux File System Hierarchy](https://upload.wikimedia.org/wikipedia/commons/thumb/d/d6/Ubuntu_Filesystem_Hierarchy.png/300px-Ubuntu_Filesystem_Hierarchy.png)](https://en.wikipedia.org/wiki/Filesystem_Hierarchy_Standard)

## Overview

Linux organizes everything into one big tree starting at `/`. The **Filesystem Hierarchy Standard (FHS)** defines what each directory means, so any Linux system feels familiar.

## Key Directories

| Path | Purpose |
|---|---|
| `/` | The root of the whole file system |
| `/home` | Per-user home directories (`/home/alice`) |
| `/etc` | System-wide configuration files |
| `/var` | Variable data: logs, spool, caches |
| `/usr` | User programs, libraries, and most applications |
| `/bin`, `/sbin` | Essential binaries (often symlinks into `/usr`) |
| `/tmp` | Temporary files, cleared on reboot |
| `/dev` | Device nodes (hardware interfaces as files) |
| `/proc` | Virtual file system exposing kernel/process info |
| `/sys` | Virtual file system for kernel objects |
| `/opt` | Optional third-party software |
| `/boot` | Kernel and bootloader files |
| `/mnt`, `/media` | Mount points for disks and removable media |

## Navigating the Hierarchy

```bash
ls /                    # top-level directories
ls /etc                 # system configuration
ls /home               # user homes
cat /proc/version       # kernel version exposed by the virtual FS
cat /etc/os-release     # which distro is running
```

## Why it matters to kernel work

- The kernel mounts devices into this tree (`mount` under `/`), and almost every subsystem shows up here — `/dev` for drivers, `/proc` for processes, `/sys` for devices.
- Many kernel debugging sessions start with `ls /proc`, `ls /sys`, or reading files under `/proc`.
