# Lesson 4.5: **Managing Users and Permissions**
[![Linux Users](https://upload.wikimedia.org/wikipedia/commons/thumb/5/5d/Linux_file_permissions.svg/320px-Linux_file_permissions.svg.png)](https://en.wikipedia.org/wiki/File_system_permissions)

## Overview

Linux is a multi-user system. Every file and directory is owned by a **user** and a **group**, and access is controlled by **permissions**.

## Basic Concepts

- **Users**: accounts that can log in and run processes. `whoami` shows your current user.
- **Groups**: collections of users that share access rights.
- **Root / superuser**: an administrator account with full control. Prefer `sudo <command>` over logging in as root.
- **Ownership**: each file has an owner (`u`), a group (`g`), and others (`o`).

## Understanding Permissions

`ls -l` shows permissions like `rwxr-xr--`:

- First character: file type (`-` file, `d` directory, `l` symlink).
- Next nine: three triples — **owner / group / others**.
- `r` = read, `w` = write, `x` = execute.

## Managing Permissions with `chmod`

`chmod` changes permissions. Use `u`, `g`, `o` (who) with `+`/`-` (add/remove) and `r`/`w`/`x` (what):

```bash
# Give the owner execute permission
chmod u+x script.sh

# Remove write for others
chmod o-w file.txt

# Set exact permissions numerically (r=4, w=2, x=1) — 754 = rwxr-xr--
chmod 754 file.txt
```

## Managing Ownership with `chown`

`chown` changes the owner and/or group:

```bash
# Change owner
sudo chown alice file.txt

# Change owner and group
sudo chown alice:developers file.txt
```

## Superuser Access with `sudo`

`sudo` runs a command as root after authentication, logging the action. List of users allowed to run `sudo` lives in `/etc/sudoers`.

## Exercise
