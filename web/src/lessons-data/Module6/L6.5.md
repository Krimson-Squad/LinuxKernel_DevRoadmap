# Lesson 6.5: File Systems in Linux

## Overview

Linux mounts many file systems at once (ext4, XFS, tmpfs, proc, ...). A single abstraction — the **Virtual File System (VFS)** — exposes them all through the same `open`/`read`/`write` interface, and lets the kernel synthesize file systems like `/proc` that have no disk behind them at all.

## VFS's core objects

- **Superblock** (`struct super_block`) — represents one mounted instance of a file system.
- **Inode** (`struct inode`) — a file's metadata: owner, mode, size, and a pointer to the operations that manage it.
- **Dentry** (`struct dentry`) — a name in a directory hierarchy; the directory-cache maps path components to inodes.
- **File** (`struct file`) — an open instance: current position, flags, and `file_operations`.

A read flows through these objects:

```text
sys_read() -> vfs_read() -> file->f_op->read_iter()
                         -> ext4_file_read_iter()   (per-fs code)
```

## Mounting and interfaces

Filesystems declare their handlers in `struct file_system_type`; `mount` populates a superblock. The implementations live in `fs/ext4/`, `fs/xfs/`, `fs/btrfs/`, and framework ones like `fs/proc/`, `fs/sysfs/`, `fs/debugfs/`.

## Exploring from the shell

```bash
mount | column -t                 # what's mounted where
df -T                             # fs type per mount point
stat /etc/hostname                # inode, size, permissions
cat /proc/filesystems             # file systems the kernel knows
```

## Suggested exercise

Trace a file read from VFS down to the filesystem: `strace -e read cat /bin/true > /dev/null`. Then open `fs/read_write.c`, find `vfs_read()`, follow it into the `file_operations` for ext4 (`fs/ext4/file.c`) and compare it to the ops for a pseudo-filesystem like `fs/proc/`.
