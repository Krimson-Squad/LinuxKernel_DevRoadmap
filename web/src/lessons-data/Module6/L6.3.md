# Lesson 6.3: Linux Memory Management

## Overview

The kernel must hand out physical memory safely, virtually, and fast. It does this with a paging model, per-CPU allocators, and a clean split between the physical (`struct page`) and virtual (`vm_area_struct`) views.

## Key ideas

- **Virtual memory**: every process sees its own address space; the MMU translates virtual → physical through page tables.
- **Paging**: memory is managed in 4 KiB (or 2 MiB) pages; unneeded pages live on disk and are faulted in on access.
- **Zones and the page allocator**: physical memory is split into zones (`DMA`, `DMA32`, `Normal`, `Movable`). The buddy allocator in `mm/page_alloc.c` hands out power-of-two chunks (order 0, 1, 2, ...).
- **Slab allocators**: small, frequently-changed kernel objects use slab/slub caches (`mm/slub.c`), avoiding the overhead of buddy allocation per-object.

## The `mm/` tree

```text
mm/page_alloc.c    buddy allocator, free lists, zone management
mm/slub.c          general-purpose slab cache
mm/mmap.c          virtual address space, do_mmap()
mm/memory.c        page fault path, huge pages, memory policy
mm/vmalloc.c       virtually-contiguous allocations
mm/ksm.c           kernel samepage merging
```

## The page-fault path (the "trap to handler" exercise)

1. Process touches a page not in the page table → CPU raises a page fault.
2. The handler in `arch/<arch>/mm/fault.c` determines the fault type (present, non-present, or protection).
3. For a valid virtual address, `mm/memory.c`'s fault code maps in a page (read from swap/file or zero-fill).
4. For an invalid address, the kernel delivers `SIGSEGV` to the process.

## Quick observation

```bash
cat /proc/meminfo          # zones, free pages, slab, swap
cat /proc/buddyinfo        # per-order free lists per zone
cat /proc/slabinfo         # cache usage
```

## Suggested exercise

Run `cat /proc/buddyinfo`, reboot-free: touch a large file with `dd`, then re-check `buddyinfo` and watch the lower-order free lists drain. Then read `mm/memory.c`'s `handle_mm_fault()` to see the fault path end to end.
