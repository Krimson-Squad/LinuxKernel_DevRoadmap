# Lesson 7.2: Configuring Your Development Environment

## Overview

Kernel development is dominated by tools and environment variables. Configure your editor, your debugger, and the handful of variables Kbuild cares about, and daily work gets much smoother.

## Editor configuration

- **Vim**: syntax highlighting, `:set tabstop=8 noexpandtab`, and tag navigation (`ctags -R .` then `Ctrl-]`).
- **VSCode**: the C/C++ extension reads `compile_commands.json` (generate with `make defconfig` + `bear -- make`), giving you go-to-definition, references, and rename across the tree.
- Linting: run `make W=1` or `scripts/checkpatch.pl` to catch issues before sending a patch.

```bash
sudo apt install ctags cscope bear
```

## Debugging tools

- **GDB** — user-space and, via `vmlinux`, kernel debugging.
- **KGDB** — in-kernel debugger; breakpoints over serial/VM.
- **KDB** — the built-in "kernel debugger" shell for backtraces and memory inspection when KGDB isn't running.
- **QEMU/kgdboc**: for VM-based kernel debugging, set `kgdboc=ttyS0` and connect qemu's serial.

## Environment variables Kbuild cares about

```bash
export ARCH=arm64                 # which architecture you're building
export CROSS_COMPILE=aarch64-linux-gnu-   # toolchain prefix for cross builds
export PATH=$PATH:~/kernel/tools   # keep helpers reachable
```

Note: `ARCH` translates to `arch/<arch>/`; leave it unset on x86.

## Verification

```bash
echo $ARCH
gdb --version
```
