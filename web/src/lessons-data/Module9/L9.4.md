# Lesson 9.4: Kernel and Hardware Interaction

## Overview

Above the drivers sit the kernel facilities that all hardware shares: interrupts, DMA, and a unified device model. Understand these three and you can read any driver.

## Interrupt handling

When hardware needs attention it raises an **interrupt**; the GIC/IO-APIC routes it to a CPU:

- **Hard IRQ handler** (`request_irq`): runs in atomic context — do the minimal, acknowledge the device, defer the rest with `tasklet`/`workqueue`/threaded IRQ.
- **Bottom halves**: `tasklet` (fast), `workqueue` (sleeping), or threaded IRQs (`request_threaded_irq`).

```c
static irqreturn_t my_irq(int irq, void *data)
{
	readl(regs + INT_STAT);          /* acknowledge */
	schedule_work(&my_work);         /* defer real work */
	return IRQ_HANDLED;
}

ret = request_irq(irq, my_irq, IRQF_SHARED, "mydrv", priv);
```

## DMA — Direct Memory Access

DMA lets the hardware read/write memory without the CPU copying. The kernel allocates DMA-capable buffers with `dma_alloc_coherent()` (or streaming APIs `dma_map_single`), keeps them physically contiguous and cache-coherent, and hands the physical address to the device:

```c
dma_addr_t dma;
buf = dma_alloc_coherent(dev, SIZE, &dma, GFP_KERNEL);
/* program the device with 'dma' address */
dma_free_coherent(dev, SIZE, buf, dma);
```

## Hardware abstraction through the kernel APIs

- **Registers**: `ioremap`/`readb`/`readl`/`writel` touch MMIO.
- **The device model** (`drivers/base/`): `struct device`, `struct driver`, buses, `sysfs` — runtime for everything (`/sys/bus/`, `/sys/devices/`).
- **PCI/USB cores** (`drivers/pci/`, `drivers/usb/core/`) handle enumeration; drivers get ready-to-use resources from `probe`.

## See the model in action

```bash
lspci
ls -l /sys/bus/pci/devices/
cat /sys/bus/pci/devices/0000:00:1f.2/class
```
