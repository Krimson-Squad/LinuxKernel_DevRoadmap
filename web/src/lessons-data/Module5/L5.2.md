## Overview

System calls are the contract between user-space programs and the kernel. When a program needs the kernel to do something — open a file, send data, spawn a process — it issues a system call.

## How a system call works

1. The program loads arguments into registers and executes a special `syscall` instruction.
2. The CPU traps into kernel space and dispatches to the handler with the matching number in the **syscall table** (`arch/x86/entry/syscalls/syscall_64.tbl` on x86-64).
3. The kernel runs the operation, then returns a value (usually via `rax`) and control drops back into user space.

## Common file system calls

```c
int fd = open("/etc/hostname", O_RDONLY);   // get a file descriptor
ssize_t n = read(fd, buf, sizeof buf);      // read bytes
ssize_t w = write(fd, buf, n);              // write bytes
int ok = close(fd);                         // release the descriptor
```

## Error handling

Syscalls return `-1` on failure and set the `errno` variable to the reason (`EACCES`, `ENOENT`, `EINTR`...). In C you check and print:

```c
#include <errno.h>
#include <string.h>

int fd = open("/no/such/file", O_RDONLY);
if (fd < 0)
    printf("open failed: %s\n", strerror(errno));
```

## Reading the syscall table

The definitive list lives in the kernel source. On x86-64:

```
arch/x86/entry/syscalls/syscall_64.tbl
```

Each row has the syscall number, ABI, name, and the C entry point. This is where system calls and their kernel implementations (`fs/open.c`, `fs/read_write.c`, ...) are linked together.
