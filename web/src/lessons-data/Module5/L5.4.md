# Lesson 5.4: **Memory Mapping in Linux**
[![yt-video](https://i.ytimg.com/vi/7aONIVSXiJ8/hq720.jpg)](https://www.youtube.com/watch?v=7aONIVSXiJ8)

## Overview

Memory mapping (`mmap`) maps files or anonymous memory into a process's address space. Reading and writing then happens directly through memory, without repeated `read()`/`write()` system calls — the kernel handles paging pages in and out for you.

## The `mmap` system call

```c
#include <sys/mman.h>

void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
```

- `prot`: `PROT_READ`, `PROT_WRITE`, `PROT_EXEC`.
- `flags`: `MAP_SHARED` (changes visible to other mappers / the file) vs `MAP_PRIVATE` (copy-on-write).
- fully mapping a file with a non-negative `fd` and `offset`.

## Mapping a file

```c
#include <fcntl.h>
#include <sys/mman.h>
#include <unistd.h>
#include <stdio.h>

int main(void) {
    int fd = open("/etc/hostname", O_RDONLY);
    char *p = mmap(NULL, 4096, PROT_READ, MAP_PRIVATE, fd, 0);
    printf("%s", p);
    munmap(p, 4096);
    close(fd);
    return 0;
}
```

The bytes of `/etc/hostname` appear in memory with no explicit read: the kernel faulted the pages in lazily on first access.

## Shared memory between processes

With `MAP_SHARED` and no file, two processes that map the same name (via a shared or media device like a file) see the *same* physical pages — the basis of fast inter-process communication.

## How it works, at the kernel level

The kernel keeps a `vm_area_struct` for each mapping. When the program touches a page that isn't resident, a **page fault** walks the area's operations and brings the page from disk (or zeros it for anonymous mappings). The same `vm_area_struct` machinery sits behind this user-space API — you will meet it again in Module 6's memory management lessons.
